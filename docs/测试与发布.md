# 测试与发布

每次代码改动遵循：分支修改 → 本地测试 → PR 自动测试 → 合并 → 按需真实环境验收 → 用户决定发布。

## 自动测试

本地运行 `npm.cmd test`，需要 Node.js 22 及以上和 Chrome。测试会启动无界面 Chrome、使用虚构数据及本机模拟页面，不会操作真实 ITSM 合同。

`.github/workflows/ci.yml` 在向 `main` push、面向 `main` 的 PR 和手动触发时运行，在 Windows 上分别使用 Node.js 22、24：

1. 从 `package-lock.json` 安装依赖。
2. 确保 Chrome 可用。
3. 运行完整的 `npm test`，包括浏览器测试；任何一步失败都使该检查失败。

## GitHub 强制检查配置

CI 文件提交并至少成功运行一次后，在仓库 Settings → Branches 中为 `main` 添加保护规则：

- 开启 **Require a pull request before merging**。单人维护时不强制第二人批准，但仍通过 PR 检查变更。
- 开启 **Require status checks to pass before merging**，将以下两个检查列为必需：
  - `Windows tests (Node 22)`
  - `Windows tests (Node 24)`
- 开启 **Require branches to be up to date before merging**。
- 开启 **Do not allow bypassing the above settings**，让管理员也遵守检查。
- 保持不允许强制推送和删除 `main`。

检查必须来自 GitHub Actions，并与当前提交匹配。只有 CI 文件而未启用上述仓库设置，无法强制阻止未测试改动进入 `main`。

## 发布要求

自动测试成功只代表已执行用例通过。涉及 ITSM 页面定位、联动或保存流程的变更，需要在目标环境核对相应行为，并按项目既有规则记录验收结果。

测试通过后由用户决定发布时间。发布前记录准确的提交 SHA、本地测试结果、GitHub CI 链接，以及适用的真实环境验收结果。发布内容来自该提交；不得混入之后未经测试的改动。

本配置只运行测试，不自动创建 Release 或替换本机正在使用的版本。
