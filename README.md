# ITSM 预算余额转合同

Windows 本机 RPA 工具。直接读取 ITSM“收费合同上药审批表”的项目编号关联列表，无需上传预算清单。仅处理“控股企业信息分摊费”，按剩余额度填写并保存待发。

## 使用

1. 双击“启动工具.cmd”，打开 http://127.0.0.1:17326 。需要 Node.js 22 及以上、配置中指定的 Chrome 或 Edge。
2. 点击“打开 ITSM 登录”，在专用浏览器中登录。
3. 确认预算年度（默认当前年度），点击“读取 ITSM 预算”。
4. 核对预览中的三项金额及本次申请金额，勾选预算，试录一条或执行所选。
5. 到 ITSM 待发事项检查草稿，发送审批由用户操作。

程序只需访问 ITSM，不调用大模型。浏览器关闭后 ITSM 会话可能失效，需要重新登录。当前工具页面只监听本机，服务器部署需要图形桌面和 ITSM 内网连接。

ITSM 专用浏览器沿用 Windows 和 VPN 已有的网络设置，程序不设置代理、不强制直连，也不修改系统网络配置。按平时能够访问 ITSM 的方式连接 VPN 即可。

## 金额规则

本次申请金额 = 分摊合计含税 −（已分摊合同金额 + 在途分摊合同金额）。

- 已分摊、在途为空白时按 0 计算，这是用户明确确认的规则。
- 分摊合计含税必须存在；非法格式、负数分量、超过两位小数或超出范围的金额禁止录入。
- 计算使用整数分，不使用浮点数。
- 余额为 0 或负数时跳过，并显示原因。
- 收费属性必须精确匹配“控股企业信息分摊费”，其他属性不进入录入列表。
- 选中预算时和保存前都从 ITSM 重新查询年度、编号、收费属性及三项金额；与预览不一致时停止，提示重新读取。
- 读取完所有分页后核对总条数，防止漏读或重复页。

## 其余字段

| 字段 | 填写规则 |
|---|---|
| 项目编号 | 精确选择 ITSM 预算编号对应行，再点确定 |
| 合同名称 | 当年年份＋年信息化分摊费用＋项目名称（关联预算名称） |
| 合同说明 | 当年年份＋年信息化分摊费用 |
| 合同签订日期 | 执行当天，北京时间 |
| 廉洁合规协议 | 不签订 |
| 合同内容 | 第一个有效非空选项 |
| 公章保管类型 | 公司保管合同章 |
| 对方公司名称 | 保留关联预算自动带出的值 |
| 对方负责人 | 直接复制下方“收款联系人”；来源为空则目标留空 |
| 对方负责人联系方式 | 直接复制下方“收款联系人邮箱”；来源为空则目标留空 |
| 合同金额和其他默认值 | 保留 ITSM 计算、联动及模板默认值 |
| 完成操作 | 保存待发 |
| 批次完成后 | 最后一条保存待发确认后关闭合同录入页，保留 ITSM 主页 |

预审领导、我方负责人联系方式、上传合同保留表单原值，自动带出非空内容时继续录入。

复制方向为下方收款联系人、收款联系人邮箱 → 上方对方负责人、对方负责人联系方式（2026-10-29 用户明确确认）。下方姓名展示控件和邮箱作为只读来源，直接将文字填入上方输入框，不打开选人弹窗。两项分别判断空值，来源为空时清空对应目标字段，避免残留。保存前、实时余额复查后和保存后均核对来源与目标一致。整批全部保存成功后只关闭一次录入页；中途停止、失败或保存结果不确定时保留页面供核查。

合同名称、说明的年份按实际执行当天的北京时间确定，与所选预算年度独立。例如：合同名称“2026年信息化分摊费用示例医药有限公司”，合同说明“2026年信息化分摊费用”。示例公司为虚构数据。页面预览和执行使用同一格式规则；原始预算说明仍用于数据变化核验，不再直接填入合同说明。

## 保存记录与恢复

实际配置在 .local/oa.json，ITSM 预览在 .local/latest-preview.json，执行历史在 .local/history.jsonl。迁移时必须保留配置和执行历史。源代码不包含账号密码。

预算以“年度 + 预算编号”识别。本机已有草稿时跳过，即使 ITSM 尚未将草稿计入在途，也不会再次创建。以前文件模式的草稿历史继续有效；旧文件预览不能执行，上传接口和上传入口已移除。

保存前同步写入状态及待核查草稿标识；保存后观察主页面和 iframe 中匹配的 summaryId、affairId 和 waitSend 草稿地址，不要求发生整页跳转或等待全部脚本加载。取得凭据后重新 GET 草稿，核对服务器响应和表单字段，以确认内容已持久保存。异常会记录页面提示、当前地址及待核查标识。结果不确定时停止批次并禁止自动重建。刷新后默认不勾选，恢复预览仍会在录入前重新核对实时余额。

## 验收

真实业务验收记录仅保存在本机，不纳入版本管理。测试使用虚构预算、联系人和草稿标识；首次接入其他环境时，需要核实页面定位及保存待发流程。

运行测试：

```powershell
npm.cmd test
```

测试覆盖余额计算、零/负余额、收费属性、空白规则、收款字段复制与空值、批次结束关闭页面、金额变化拦截、防重复、读取互斥、保存凭据、旧版 Set 兼容、预览恢复和接口鉴权。旧 Excel/CSV 解析模块保留用于兼容性测试，产品不再提供上传流程。
